# Optional Remotion animation mode

MEGA RECORDER `v0.4.0` includes an optional, local Remotion integration for
rendering declarative animation manifests. It is a separate runtime under
`integrations/remotion/`; the upstream OpenScreen app remains version `1.10.0`
and the recording path is unchanged.

Remotion is not required for recording-only work. A recording checkout can be
bootstrapped, inspected, and used with `record`, `edit`, `audio`, `scenes`, and
`verify` without installing the optional animation dependencies. Animation-only
work also does not require Electron, native capture helpers, or the local
Kokoro runtime when the manifest contains no narration audio.

## Check and install the optional runtime

Run the product CLI from the repository root:

```bash
npm run --silent mega-recorder -- animation doctor
```

The doctor reports whether the Remotion integration files and its local
dependencies are present. A missing optional runtime is a capability report,
not a recording failure.

When animation rendering is needed, install the isolated dependency set with:

```bash
npm run --silent mega-recorder -- animation setup
npm run --silent mega-recorder -- animation doctor
```

Setup is intentionally scoped to `integrations/remotion` and does not install
or enable native capture, Electron, or Kokoro. Do not run setup merely to make
a recording-only checkout compatible.

## Create and validate a manifest

Generate a starter manifest and its sibling `.src/` composition directory,
then edit them as ordinary project files:

```bash
npm run --silent mega-recorder -- animation init ./demo.animation.json
npm run --silent mega-recorder -- animation validate ./demo.animation.json
```

The manifest contract is [`integrations/remotion/manifest.schema.json`](../integrations/remotion/manifest.schema.json).
It uses `schemaVersion: 1`, a `mode` of `animation` or `mixed`, an output size
and frame rate, and one or more scenes. Scene elements can be title cards,
diagrams, or local video segments; scene audio is frame-addressed local media.
Remote assets are rejected by default. Set `allowRemoteAssets: true` only when
that deliberate change is acceptable for the project.

A minimal silent animation manifest is:

```json
{
  "schemaVersion": 1,
  "mode": "animation",
  "fps": 30,
  "width": 1920,
  "height": 1080,
  "scenes": [
    {
      "id": "title",
      "durationInFrames": 90,
      "background": "#101827",
      "elements": [
        {
          "type": "title",
          "text": "MEGA RECORDER",
          "subtitle": "Optional animation mode",
          "x": 50,
          "y": 50,
          "align": "center",
          "color": "#ffffff",
          "accent": "#65d6ff"
        }
      ],
      "transition": { "type": "none", "durationInFrames": 0 }
    }
  ],
  "output": "./dist/demo-animation.mp4"
}
```

Validate before rendering. Validation is schema/input checking; it does not
prove that a render has completed or that the output media is playable.

Scene transitions overlap adjacent scenes: a transition on scene *n* must not
be longer than either scene *n* or scene *n+1*, and the final scene must use a
zero-duration transition. The normalized timeline length is
`sum(scene.durationInFrames) - sum(transition.durationInFrames)`. Audio clips
are local and frame-addressed; each clip must satisfy
`startFrame + durationInFrames <= scene.durationInFrames`.
For example, a 3-second, 30-fps narration clip beginning at frame 0 is
`{"src":"./narration.wav","startFrame":0,"durationInFrames":90}` inside a
scene's `audio` array. Audio source files are not generated by Remotion; create
or copy them locally and verify them separately.

## Project-local React compositions

The declarative scene elements are the default path. For custom React motion,
keep the source in the animation project rather than editing the installed
runtime. `animation init` already creates an editable scaffold and sets the
manifest's `entryPoint`. For an existing hand-written manifest, the scaffold
can also be copied manually:

```bash
mkdir -p demo-animation/src
cp integrations/remotion/src/index.jsx demo-animation/src/index.jsx
cp integrations/remotion/src/composition.jsx demo-animation/src/composition.jsx
```

Use a project-local value such as `"entryPoint": "./src/index.jsx"`, keep all
custom imports and media inside that project, and run `animation validate` and
`animation render` against the manifest. The renderer does not overwrite the
entrypoint. This path is intentionally source-editable; a successful scaffold
copy or validation still does not establish that a custom composition renders
correctly, so inspect and verify its emitted media.

## Render or preview

With the optional runtime installed and a valid manifest:

```bash
npm run --silent mega-recorder -- animation render ./demo.animation.json
npm run --silent mega-recorder -- animation preview ./demo.animation.json
```

Rendering writes the manifest's `output` path; pass `--output ./dist/other.mp4`
to override it for one render. Preview starts a loopback-only
server and prints its URL; it does not launch a browser. Open that URL
explicitly in the Codex in-app browser or Brave. Do not use Chrome for this
workflow. Preview and render use local files by default and do not need an AI
provider or API key.

Preview has playback and scrubbing controls. Its per-run URL token establishes
an HttpOnly cookie; only the bundle and referenced media are served. Keep the
process running while previewing, then stop it with Ctrl-C. After source or
manifest edits, restart preview to load the revised composition.

The default composition supports title cards, diagram cards, local video
segments, overlap-aware fade/slide transitions, and local audio. A project-local
custom entry point may be used for more bespoke motion, but the renderer does
not write to that source. This integration has not been promoted as a native
recording replacement: native capture, desktop permissions, and upstream
Electron behavior remain separate concerns.

Treat `doctor` as a local capability check, not a release-readiness claim. A
fresh render must be inspected and verified with the emitted media (for
example, with the product `verify` command), and platform-specific behavior
must be tested on the target host.
